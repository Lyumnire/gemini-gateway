# 抓取官网模型内部 ID（一次性，约 5 分钟）

目的：官网模型选择器（3.7 Flash / 3.5 Flash-Lite / 3.1 Pro）的内部 ID 不在
协议层静态页面里，是登录后动态下发的。抓一次官网发出的请求，就能拿到真实
ID（以及生图功能的请求标志），把它们固化到网关里。

## 步骤（在已登录 Gemini 的 Edge 里操作）

1. 打开 <https://gemini.google.com>，按 `F12` 打开开发者工具，切到
   **网络 / Network** 标签。
2. 在过滤框输入 `StreamGenerate`。
3. 在官网输入框把模型切到 **3.1 Pro**，随便发一条短消息（比如 `hi`）。
4. 网络面板会出现一条 `StreamGenerate` 请求 → 右键它 →
   **Copy（复制）→ Copy request payload（复制请求负载）**。
   > 只复制"请求负载"即可，不需要带 Cookie 头，安全。
5. 把模型切回/切到 **3.7 Flash** 与 **3.5 Flash-Lite**，各重复一次第 3-4 步。
6. （可选，用于修生图）在官网让它**生成一张图片**，同样复制那条请求负载。
7. 把复制的 3-4 段负载文本发给网关维护流程即可。

## 我拿到后做什么

- 从 `f.req` 里提取模型字段（inner 数组第 4 个元素），对比三个选择项的 ID；
- 把真实 ID 加入后端白名单（`backend/src/.../gemini_service.go` 的
  `extraModelIDs`），重建后端；
- 若抓到生图请求，对比普通聊天的请求差异，补上缺失的标志位；
- 前端下拉框从此就是真实可选的 3.1 Pro / 3.5 Flash-Lite / 3.7 Flash。
